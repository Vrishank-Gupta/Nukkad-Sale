## Fixed

- Old brand: the browser-tab icon on every app page was a ⚡ emoji; the login screen showed a big ⚡; the
  "Publish & get link ⚡" button. Now the storefront icon.
- Emoji used as UI (against the "line icons, no emoji" rule): website feature icons (9), admin buttons
  and banners (📞 Call, ✅ Shop created, 🔑, ⬇ Export, 💬, ✅/⬜ checklist, "Nothing here 🎉"), help-guide
  button, "Thank you! 🎉", 👇/⬆️/🎉 in app messages. WhatsApp message text keeps its emoji.
- Website header overflowed sideways by 25 px on 320 px phones ("Get started" wrapped/clipped) – fits now.
- Tap targets: header icon buttons and small buttons 36–38 px → 40 px; footer links 16 px → 36 px tall;
  order tabs and "← Home" back links 40 px.
- Accessibility: stock / size / quick-order quantity inputs had no label; stepper buttons read "+"/"−"
  (now "More"/"Less"); seller home, buyer order page and thank-you page had no `<h1>`.
- Tests brought up to date: tour (site now uses "Get started"), PWA (app starts at /login), tour stock.

## Verified (no change needed)

- A stopped sale shows "This sale has ended" and no Pay button; buyers can't pay.
- Sold-out / all-held sale shows the right message; Pay disabled.
- Invalid phone/pincode is refused; returning buyers' details are remembered.
- Carts: two products, one payment, amount below the total.
- Razorpay (mock): admin switches it on per shop, buyer pays, order shows "Payment received!".
- Signup is closed in production and `/signup` sends people to "Get started".
- No page has the old name; every internal link resolves; 404s are friendly.

## Known, by design

- The shop name in the header is a 28 px-tall link (logo), and size pills use visually hidden radios –
  the audit lists them as small targets; they're fine.
- The marketing site (`/`) doesn't register the service worker; the installable app starts at `/login`.
